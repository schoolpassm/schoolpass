# 학교알리미 동기화 — 미매칭 학교 자동 생성

## 문제
"학교알리미 공공데이터 동기화" 기능은 원래 DB에 이미 있는 학교의 학생수/학급수 등을
업데이트만 하고, 매칭 안 되는 학교(DB에 아예 없는 학교)는 그냥 건너뛰었습니다.
그래서 경북/경남/제주처럼 DB에 통째로 빠진 지역은 물론, 전북처럼 이미 데이터가 있는
지역 안에서도 원래 빠져있던 개별 학교들은 동기화를 아무리 돌려도 절대 채워지지 않았습니다.

## 수정
"학생수·학급수" 카테고리에 한해, 이름/지역으로도 매칭 안 되는 학교는 이제 **새 학교
문서로 자동 생성**합니다.
- 문서ID는 학교알리미의 SCHUL_CODE를 그대로 사용 — 다음 동기화부터는 문서ID로 바로
  매칭되어 중복 생성되지 않습니다.
- 생성되는 필드: 학교명, 지역, 학교급, 학생수/학급수, 교육지원청명(있으면), 상태="신규",
  등급="C", 주소/전화/담당자 등은 비워둠(직접 입력 필요) — 학교알리미 공시자료를
  그대로 옮기는 것이라 스펙 16번(확인 안 된 정보 임의 생성 금지)에 저촉되지 않습니다.
- 다른 카테고리(교직원수/학교회계 등)는 정보가 빈약한 반쪽 레코드가 생기지 않도록
  기존처럼 건너뛰기만 합니다 — "학생수·학급수"를 먼저 돌려서 학교를 만든 뒤, 다른
  카테고리로 나머지 정보를 채우는 순서를 권장합니다.
- Firestore 배치 쓰기 상한(500) 안에서 항상 여유 있게 끝나도록 내부 청크 크기를
  300 → 200으로 낮췄습니다 (학교 1곳 생성 시 detail+summary 2건씩 쓰기 때문).

동기화 결과 화면에 "신규 학교 N건 생성"과 생성된 학교명 샘플이 추가로 표시됩니다.

## 사용 순서 (경북/경남/제주 채울 때)
1. 데이터 종류: **"학생수·학급수"** 선택 (이게 있어야 신규 생성됩니다)
2. 시/도: 경상북도 (또는 경상남도, 제주특별자치도)
3. 학교급: 처음엔 1개만 (초등학교부터 추천)
4. "동기화 실행" — 결과에 "신규 학교 N건 생성" 확인
5. 필요하면 다른 카테고리(교직원수, 학교회계 등)로 같은 시/도 재동기화 — 이번엔 방금
   생성된 학교들도 문서ID로 바로 매칭되어 정보가 채워집니다
6. `/schools` 화면에서 "좌표 채우기(지도용)" 버튼으로 지오코딩 → 지도/방문동선에 표시

`npx tsc --noEmit` 통과 확인 완료.
